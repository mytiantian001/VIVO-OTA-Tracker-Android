# ADR-002：OTA 包内文件的文件管理器式浏览与预览

- **状态**：已接受
- **日期**：2026-08-30
- **相关**：`docs/ADR-001-ota-zip-browser.md`、`docs/GLOSSARY.md`

## 背景

ADR-001 交付了 L0 层能力（列条目、预览、下载），但界面呈现被指出「不直观」，
嵌套 zip 时尤甚。经排查，根因不是缺少功能，而是**视觉层级混乱**：

1. 包内文件是折叠 Card，与 ROM 信息、分区列表**共用同一个 `LazyColumn`**，它是「段落」而非「地方」
2. 嵌套 zip 后仅替换列表内容 + 标题下方一行小字路径，没有「进入 / 退出」的空间感
3. 列表在主页面、预览在 Dialog，两套割裂的视觉体系

## 关键事实（决定方案边界）

| 事实 | 影响 |
|------|------|
| zip 中**显式目录条目数为 0**，全部是扁平路径 | 「文件夹」必须靠路径前缀**合成**，不是 zip 固有结构 |
| 深度分布极端（实测 289 条目：`0层:13 / 1层:65 / 2层:62 / 3层:14 / 4层:5 / 5层:2 / 6层:128`） | 纯树形逐级点进深层是灾难 |
| 顶层聚类极强（`org→128`、`META-INF→71`、`res→41`） | 合成**一层**文件夹收益立竿见影 |
| OTA 包结构普遍很浅（`payload.bin` + `META-INF/**`；recovery 包 221 个 `.img` 基本平铺） | 完整树形导航收益接近零 |

> 上述深度分布取样自 APK。本工具主要面对 OTA 包（结构更浅），
> 但方案须在遇到深包时不退化，故取混合策略。

## 决策

### D1：包内文件占据独立全屏页面，不再内联展开

Dumper 页的「包内文件」卡片改为**入口**（显示「N 个文件」概览），点击进入全屏浏览页。

- **否决底部弹层**：Dialog 的返回键会直接关闭整个弹窗，用户点进两层嵌套后按返回会丢失全部导航状态。全屏页面的系统返回键天然对应「退出一层」。
- 页面状态在 `PayloadDumperScreen` 内部用状态机管理，保持 payload 模块自洽，不侵入 `VivoApp.kt`。

### D2：目录采用「顶层合成 + 深层平铺」混合策略

- **顶层**按路径首段合成文件夹（如 `META-INF (71)`），点击进入。
- **进入后该层内部平铺**，不再往下套——避免深路径逐级点入。
- 根目录散装文件（如 `payload.bin`）单独归为「文件」分组，不与合成文件夹混排。
- 排序：文件夹组在前、散装文件在后，各自按名称字典序（文件管理器通行惯例）。

### D3：搜索仅限当前层级

- **否决全局搜索**：遍历未打开的嵌套 zip 需逐个完整下载（DEFLATE 无法部分解压），流量不可控，与 ADR-001 前提冲突。
- **否决「跨已加载层级」**：用户难以理解为何有的嵌套包能搜到、有的搜不到，不确定性比能力缺失更糟。
- 语义固定为「搜索永远只在你能看见的这一层」；结果为空时提示可进入嵌套包继续搜索。

### D4：预览为二级全屏页面，底部固定操作栏

- **否决沿用 Dialog**：预览内容可能很长（`updater-script` 数十 KB），Dialog 限高 460dp 过于憋屈。
- 文本区可滚动、可选中（`SelectionContainer` + 原生 `BasicText`），底部常驻「复制」「下载」。
- 「加载完整内容」是**状态相关的一次性动作**（加载完即消失），故置于文本区下方紧跟截断提示，而非常驻底部。

### D5：顶栏标题动态显示当前层级

形如 `ota.zip / nested.zip / META-INF`，过长时中间段省略（`ota.zip / … / META-INF`）。

- 顶栏已有返回箭头，标题直接表达「我在哪」最直观，不额外占垂直空间。
- **否决面包屑条**：浅结构下浪费空间，而 OTA 包恰恰普遍很浅。
- **否决「标题显示当前层名 + 路径作副标题」**：返回箭头 + 标题会让人误以为退到上一层，实际退的是同级目录，语义含混。

### D6：平铺条目用单行混合样式显示路径

路径段灰色小字、文件名正常字重，一行显示 `com/android/metadata`。

- 只显示文件名会丢失所在子目录信息，平铺深层内容时同名文件将无法区分。
- 全同粗细则扫读时抓不住重点。
- 单行混合不增加行高，兼顾完整性与紧凑。

### D7：进入页面即自动加载

读取 central directory 仅消耗「尾部 4KB + 目录区」，与包体大小无关，无需用户手动触发。

### D8：嵌套 zip 不伪装成目录

它外形像文件夹但本质是文件，故仍作为条目显示，右侧提供「打开」按钮进入新层级。
沿用 ADR-001 的 10MB 红线（内层需完整读出才能定位其 central directory）。

## 与 ADR-001 的关系

ADR-001 的解析层、数据层与红线策略**全部保留**，本 ADR 仅改变呈现层：

| ADR-001 决策 | 本 ADR 影响 |
|---|---|
| D1 L0 层级、D2 两类包都支持 | 不变 |
| D3 10MB 双阈值红线 | 不变（含嵌套 zip 进入条件） |
| D4 MediaStore 落盘 | 不变 |
| D5 预览 8KB 预取 | 不变 |
| D6 白名单 + 嗅探 + NUL 拦截 | 不变 |
| D7 编码自动检测 | 不变 |
| D8 可复制 + Binder 上限保护 | 不变，**载体由 Dialog 改为全屏页** |
| D9 复制已加载部分 | 不变 |
| **D10 UI 落位（可折叠区块）** | **被本 ADR D1 取代** |
| D11 单选下载 | 不变 |
| D12 CRC32 校验 | 不变 |

## 后果

**正面**
- 包内文件获得独立空间，与分区列表的层级冲突消除。
- 嵌套导航获得「进入 / 退出」的空间感，且返回键语义正确。
- 混合目录在浅结构（OTA 包主流）下接近完整树形的效果，在深结构下不退化。

**负面 / 代价**
- 查看一个 300B 的 `payload_properties.txt` 也需进入二级页面，比 Dialog 多一步。
- 需维护页面状态机（浏览页 / 预览页 / 列表页三态）。
- 深层平铺时条目仍可能较长（D6 已用字重分层缓解，但未根除）。
